# 웹 런처와 게임 11종의 배포 설정 복원

`deployment/public-launcher.json`은 이 릴리스의 목표 운영 설정이다. 실제 호스팅 상태는 운영 환경에서 별도로 확인한다. 이 파일의 키를 `.openai/hosting.json`에 복사해도 접근 권한과 런타임 환경 변수는 적용되지 않는다.

1. 통합 ZIP 최상위의 `prepare-workspace.py`로 개발 작업 공간을 복원한다. `games/<게임 ID>` 11곳에 런처 게이트웨이와 세이브 연결 코드가 설치된다. `lucid-game-launcher`에는 웹 런처가 들어 있다.
2. 기존 운영판을 복구할 때는 선언의 `originalProjectId`와 각 프로젝트의 `.openai/hosting.json`을 대조한다. 기존 사용자 진행을 이어가려면 해당 프로젝트의 데이터베이스와 오브젝트 저장소를 그대로 연결한다. 새 소유자의 별도 서비스라면 새 프로젝트를 생성하고 해당 프로젝트 ID와 저장소를 사용한다. 새 빈 저장소에는 기존 사용자의 계정·슬롯이 존재하지 않는다.
3. 데이터 바인딩은 선언의 `bindings`를 따른다. 런처는 R2 `BUCKET`을 사용한다. 게임은 각자 자신의 `BUCKET`을 사용하고, 9개 비실시간전략 게임은 각자 D1 `DB`도 사용한다. 빈 프로젝트의 게임 테이블은 각 게임에 포함된 마이그레이션을 적용하여 만든다.
4. 런처와 11개 게임 원본의 호스팅 접근 권한을 선언의 `PUBLIC`으로 설정한다. 런처에서는 호스팅 서비스의 ChatGPT 로그인을 사용한다. 로그인 사용자의 ID·이메일은 호스팅 서비스가 검증하고 Worker에 전달해야 한다. 브라우저가 보낸 인증 헤더를 그대로 신뢰하는 일반 프록시로 대체하면 안 된다. 게임 원본의 `LUCID_LAUNCHER_ONLY`에는 문자열 `1`을 설정하고 `LUCID_HUB_ACCESS`는 설정에서 제거한다. 공개 런처에 연결하는 교환 요청에 비공개 서비스용 인증 토큰은 필요하지 않다. 게임별 세션 토큰은 로그인 후 런타임에서 생성된다.
5. 게임별 게이트웨이를 포함한 소스를 각각 빌드·배포한다. 최초 이전 중에는 기존 운영 슬롯에서 읽기·이어하기가 확인된 게임부터 런처에 연결한다. 전체 복구의 최종값은 런처의 `environment.LUCID_READY_GAMES` 문자열이다. 이 값을 런처 런타임에 그대로 설정하고 웹 런처를 빌드·배포한다. 호스팅 환경 변수 변경 후에는 해당 프로젝트를 새 설정으로 배포한다.
6. 로그아웃 상태의 새 창에서 웹 런처가 열리고, 게임 선택 시 런처 로그인이 요구되는지 확인한다. 로그인 후 같은 계정으로 각 게임을 실행하고, 기존 슬롯을 연다. 이전 ID 연결이 필요한 슬롯은 런처의 기존 계정 연결 기능으로 이전 계정의 소유권을 확인한다. 저장 후 브라우저를 다시 열어 이어하고, 통합 세이브 내보내기·가져오기의 슬롯 내용도 확인한다. 개별 게임 주소에 직접 접속한 경우 런처로 이동하고, 예전 개별 패키지 주소에서 파일을 받을 수 없어야 한다. 모바일에서는 두 RTS의 실행 버튼이 비활성이고 두 게임의 저장 데이터는 통합 백업으로 보관된다.
7. 자체 도메인을 사용하는 복제본은 선언의 원본 URL과 소스에 설정된 런처·게임 허용 대상도 함께 변경한다. 웹 런처의 `src/worker.mjs`, `web/app.js`, 게임 게이트웨이의 `integration/gateway.mjs`, 데스크톱·모바일 런처에서 참조하는 원본 URL을 새 도메인과 일치시킨 뒤 모든 대상 앱을 다시 빌드한다. 새 운영자의 다운로드 저장소에 런처와 게임별 모듈을 등록한다.

앱 서명 키, 실사용자 세이브, 로그인 토큰은 운영 환경마다 별도로 관리한다. 런처의 선택적 릴리스 업로드 API를 운영하는 경우 해당 운영자용 비밀키는 런타임의 비밀 변수로 관리한다. 이 값은 사용자를 로그인시키거나 게임 원본을 연결하기 위한 자격증명이 아니다.


## 런처 다운로드와 계정 분리

데스크톱은 실행 파일이 든 ZIP, Android는 APK, iOS는 기기용 IPA를 배포한다. 모바일 기기에 게임 콘텐츠를 함께 넣지 않는다. 게임 모듈의 버전, 바이트 수와 SHA-256을 src/modules.json에 기록한 뒤 deployment/upload_release.py로 원본 모듈을 등록한다. 네이티브 런처는 다운로드가 완료된 모듈의 해시를 확인한 다음 로컬 실행 대상으로 활성화한다. 두 RTS는 데스크톱에서만 실행한다.

기기 런처의 ChatGPT 계정 연결은 브라우저에서 앱에 표시된 코드를 승인하는 방식이다. 이전 기기 기본 프로필과 각 계정의 세이브는 독립적이며 내려받은 콘텐츠는 공유한다. 마지막으로 연결한 프로필은 오프라인에서도 읽을 수 있다. 기존 웹 세이브 연결은 저장 관리에서 이전 게임의 인증을 확인한 뒤 실행한다. 통합 파일에서 같은 슬롯 번호가 충돌하면 복원할 기록을 선택할 수 있다.

웹 앱과 운영 소스 ZIP은 별개로 배포한다. 공개 소스 ZIP은 GitHub의 Lucid Games 릴리스에서 배포하고 SHA256SUMS.txt와 대조한다. 웹 런처의 프로젝트 링크와 기존 /download/source 주소는 GitHub 프로젝트 페이지로 연결된다. 인증 정보나 실제 사용자의 진행은 개발 소스에 포함하지 않는다.
